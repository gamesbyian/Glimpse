# Glimpse visual grammar · production A / revision 0.1
**Draft implementation contract.** This is a cross-agent proposal, not an owner-approved design system. Integration (#10) controls any final revision lock. Supersedes neither Android native behavior nor the eight owner decisions.

## Principles
1. **Meaningful reel, ordinary controls elsewhere.** The tactile paper reel navigates finite photographs or collections; do not decorate unrelated Settings, diagnostics, rule, permission or backup screens with a wheel. A five-aperture viewport never implies an infinite carousel. Expose Grid, Previous and Next with equivalent selection semantics. At N=0/1/3/5/22/60, show finite bounds and real count.
2. **Truth above flourish.** Separate locally selected preview, saved edited copy, last *Glimpse*-acknowledged apply, and current Android Home/Lock state (unknown unless actually verified). No selection, edit, save, or share silently applies. “Set wallpaper…” enters an explicit target/action transaction. Shuffle cadence is best-effort/foreground eligible; never guarantee five-minute background alarms.
3. **One clear job per surface.** Headline describes what to do; key source/context above fold; primary call to action belongs in the bottom reachable action zone (approximately y=714–802 on the 401×890 study); secondary actions are explicit, visually subordinate. Reserve OS-native pickers, Sharesheet, wallpaper chooser and permission panels for Android, not invented in-app replicas.
4. **Paper texture is character, not information architecture.** Warm neutral canvas, readable ink, photographic content when identity and rights can be established; quiet teal active controls, coral only for attention/destructive warnings, lavender as an optional selection accent. Use simple rules/dividers rather than stacks of identical 105px cards.
5. **Source identity stays explicit.** All pXX labels denote distinct sources, never substitute one photo for a different ID. No claim of photo rights without provenance. Unresolved assets show an explicit sample/illustration label.

## Token proposal (see tokens.v0.1.json)
- Frame: 1160×920 study containing **401×890** phone crop at x=15,y=14; status/header 56–142; content 146–806; nav 823–879; proposal-only footer bottom 890–903. App content is not drawn under system bars.
- Palette: paper `#F6F0E6`, surface `#FFFCF6`, ink `#153F46`, active teal `#1D5960`, readable secondary `#566861`, border `#C8B7A1`, warning `#A5482D`; active text white `#FFFFFF`. Contrast calculated WCAG ratios on paper: ink 10.12, teal 6.99, secondary 5.22, warning 5.20; white-on-teal 7.92. Legacy `#667975` on paper is only 4.07 and should not be used for normal-size text there.
- Type scale on nominal phone canvas: display 30–32, section 21–23, row 17–18, body 15–16, secondary 14–15, metadata >=13 only when redundant with accessible names; mobile accessibility must support 200% font scale by real reflow, not by shrinking text. Sans defaults (Android implementation to resolve to available font fallback), not decorative script for functional copy.
- Spacing: 8-point rhythm, 16–20 horizontal margins, 8–12 between related content, 20–24 between sections; rounded corners 12–18, pill radius 20–24. Avoid giant empty gutters, clipping, truncating key commands and invisible horizontal actions.
- Targets: interactive rows and buttons at least **48dp** in native design intent; static SVG approx 48 units minimum height at 401 reference, with minimum 8-unit separation unless full-width list rows; icon-alone hitbox 48×48. Explicit pressed/focus/selected/disabled/error/loading styling; disabled *also* state why unavailable.
- Navigation: four destinations **Home / Discover / Collections / Automation** with current destination indicated by both color and non-color cue, and always available conventional Back/Close to reverse subflows. Do not put Settings in a fifth bottom tab; enter via header/settings affordance.
- Semantic focus: header/Back → scene content → relevant contextual row controls → primary action → secondary actions → nav; wheel each aperture receives id/index and label; current selected item announces stable id and “item i of N”, boundary stops announce end; Grid and buttons are equivalents. On interrupted OS handoff focus returns to the invoking action/status. Errors announce reason, next action and whether a durable copy survives.
- Compact 320dp: do not simply scale a fixed 401 SVG. Switch 3-wide actions to stacked or two-row controls; secondary info wraps; keep actions 48dp and accessible; permit vertical scroll for forms/settings, but no hidden command; fixed nav respects insets. 200% and TalkBack remain **native acceptance gates**, not SVG pass marks.

## Reusable primitive recipes
`PageHeader(title, context, back/overflow?)`: 56–146; `SurfaceListRow(title, detail, trailing action)`: at least 64h and real row affordance; `ChoiceGroup(label, choices, selected, explanation)`: radio-like visible selected marker + text; `StateStrip(status, evidence class, action?)`: context/time with clear unknown/failed state; `PrimaryAction(label)`: strong teal with white text, 48–56h; `SecondaryAction(label)`: light paper with ink/border, 48h; `WarningStrip(reason, action)`: warning ink and icon+text, never color alone. `BottomDestinations`: existing four tabs with labeled current destination, touch size to be tested natively.


## Rev 0.1 production errata · concrete optical findings

These are proposed refinements to the same provisional grammar, **not a frozen contract**:

- **Never put control affordances into a Unicode glyph and assume a font will provide it.** Direct 401×890 optical rendering caught square/tofu search, status and chevron glyphs; Quick Import's close and search are now explicit vector paths. For arrows and selection marks, use source-editable line paths or deliberately verified icon assets; compare pixels at the actual target font before any acceptance.
- **Quick Import exits deliberately and never silently applies.** Screen has a 48-unit Close touch study, >=50-unit Rotate/Crop/Original controls, a prominent 52-unit **Just save a copy**, and separate >=50-unit Show next and Apply… actions. The changed geometry intentionally supersedes the old source-regression assertion for 44px buttons; integration should update shared tests after independently reviewing the plate.
- **Typography and safe-area overflow require responsive layouts.** A concrete [two-state 320dp / 200%-text Sections alternative](../proposals/whole-product-candidates/compact-320dp-200pct-sections-sheet.svg) preserves four destinations via a large labeled sheet when four simultaneous tab labels are too crowded. This is **unselected**; real native text reflow, TalkBack order and owner preference remain blockers under #13.
- **Identity and rights are separate evidence dimensions.** The [p04 Home photograph candidate](../proposals/whole-product-candidates/home-p04-photographic-cc0.svg) uses exact independent C-verified CC0 JPEG bytes, retains p12 as a distinct selection and says Android-current status is unknown. The [Grid provenance candidate](../proposals/whole-product-candidates/grid-photography-provenance-p12.svg) replaces p06/p07 schematic tiles with CC0 JPEGs, shows *four clearly labeled original non-photo fallbacks* p08/p09/p16/p17, and preserves the existing p12 image identity. The remaining p10–p15 research JPG rights are still **unverified**, so no broad photographic rights acceptance is implied. Source assets and credits are owned by C #12, selection by integration #10.
- **Source checks, raster checks, Android evidence and human approval are four separate gates.** Agent A's [focused workflow](../../.github/workflows/glimpse-agent-a-primary-proof.yml) runs 18 exact source/raster checks, p04 & Grid byte-identity validators, and publishes source-indexed PNG/JPEG evidence. A successful static run cannot qualify Android's three-column Grid, OS target chooser, 320dp/2x accessibility or owner approval.

## Provisional 0.1.1 contextual contrast refinement (2026-10-25)

Production B's independent source-AA audit found a real token limitation: the existing `secondary=#566861` is readable on paper but measures only **4.27:1** on warm tan `#EAD9BD`, under WCAG AA 4.5:1 for normal-size text. This is not a flaw in B's repaired storyboards; B correctly used a darker contextual ink.

- Retain `secondary=#566861` for paper and white surfaces; don't silently repaint every ordinary label.
- Use provisional `secondaryOnTint=#445851` for small functional captions on lavender `#E9E0F5`, blush `#F5DDDA`, tan `#EAD9BD`, sage `#DAEDE1`, and sand `#F5E6D1`. Contrast on those surfaces respectively: **5.96, 5.88, 5.49, 6.22, 6.20:1**. The exact foreground/background must remain a painted solid color for this source-only claim.
- Use provisional `attentionText=#703B27` for semantic pointer/attention text on those pale backgrounds. Avoid `#E8876C` as normal-size pointer glyph text: it is **2.28:1** on paper. Decorative accents that are not conveying required information are a separate review case.
- Updated **22 actual small notice descriptions** in **16 primary SVG plates** from the paper color to stronger tint color. Their source edit does not change photo identity, layout, actions, or native implementation. Two other primary plates contain no sand note. A [fail-closed contextual contrast validator](validate-contextual-contrast.py) checks the provisional tokens, all known opaque tinted backgrounds, the 22 modified caption declarations, and synthetic old-color negative canaries; A's own focused CI runs this alongside the ordinary 18-phone renderer.

This provisional extension is **not a frozen owner aesthetic choice or native WCAG certification**. Complex alpha/image-backed text, keyboard focus, 200% text, and TalkBack still need separate proof. B's 56 repaired P0/P1 storyboard frames remain B-owned and are not rewritten by A.
